# Agent routing and usage

Ensync's shared task is provider-neutral. A handoff keeps the same conversation, canonical project, `.relay` feature memory and plan, root `CLAUDE.md` and `AGENTS.md` adapters, and host-verified Git branch/status. Vendor session IDs remain provider-specific below the Ensync task identity, and terminal/runtime state is preserved only when Ensync Host can verify it.

The provider catalog uses a deterministic mainstream-recognition navigation heuristic rather than measured market share: Codex, Claude Code, GitHub Copilot CLI, Cursor Agent, Google Antigravity, Google Jules, Kimi Code, Kiro CLI, Junie CLI, GitLab Duo CLI, Warp Oz, Factory Droid, Amp, Augment Auggie, Qoder CLI, CodeBuddy Code, then the separate local Ollama fallback. Only Claude Code and Codex currently have tested structured Ensync Host chat runners, so they are the only providers eligible for automatic fallback. Every other provider is explicitly discovery-only until it has a tested event parser, subscription-auth guard, session adapter, billing/overage guard, and no-activity retry proof. Factory Droid now satisfies the event-parser, session-adapter, containment, and no-activity retry parts of that list and is promoted to `supported` with a credential-file auth probe. It is in the automatic fallback order after Codex and Claude; because Ensync has no `/limits` quota adapter, its usage is unknown and Auto routing considers it only when no higher-priority connected provider has verified remaining capacity. Jules is a cloud-session agent rather than a local worktree subprocess, and Ollama is local rather than subscription-backed.

Gemini CLI is not in the consumer subscription route. Google stopped Gemini CLI requests for the consumer Individual, Google AI Pro, and Google AI Ultra tiers on June 18, 2026; Antigravity is the current local Google subscription CLI and Jules is the Google cloud-session agent. Qwen Code's current Coding Plan, Mistral Vibe, Aider, OpenCode, Cline, Continue, Goose, OpenHands, and other API-key-backed shells are not subscription-account providers in this catalog. CodeRabbit is review-specific rather than a general coding agent. Ensync must never repurpose one vendor's subscription credentials for another CLI.

Never replay a task on another agent after a mutating tool call. Preserve the transcript and shared project context during safe handoff.

Usage telemetry has an explicit kind: `subscription_quota`, `session_only`, `local_runtime`, or `unavailable`. It records plan, model, source, percentage, reset time, details, and last check only when the CLI reports those values. Ensync does not estimate subscription usage or turn local hardware state into a made-up percentage. Codex uses the official local app-server `account/rateLimits/read` and `model/list` methods after an authenticated ChatGPT login. Claude runs its documented local `/usage` command in safe, tool-free, non-persisted structured mode and accepts the result only when the CLI proves zero API duration, zero model turns, zero tokens, and zero cost. Claude Code 2.1.223 reports its all-model weekly reset as an exact localized schedule such as `Aug 9 at 1am (Asia/Jerusalem)`, but omits the year and an absolute timestamp; Ensync preserves that version-gated label and window for display while keeping `resetAt: null` instead of deriving a calendar date. Unsupported versions or formats keep the label null with a factual reason. For provider routing, Ensync takes the greatest exact provider-wide percentage across Codex quota windows or Claude's current-session and all-model weekly windows; model-specific Claude limits remain informational and do not replace the provider-wide figure. Ollama runs the non-generative `ollama list` and `ollama ps` commands and reports the exact installed/loaded model counts plus its actual model catalog; it never claims a subscription quota. Exact per-run token counts are aggregated by provider/model only when returned by a completed CLI process; unavailable fields stay blank with a reason.

Provider status updates automatically without making every native window launch duplicate CLI probes. Visible renderers request the non-forced `/api/providers` view once per minute and immediately when their window regains focus or visibility. Hidden windows slow to five minutes; Host failures use exponential retry backoff capped at five minutes. The single Host owns a 60-second cache and one shared in-flight refresh, so simultaneous window reads receive the same real probe. Manual Refresh remains an explicit forced check but joins any probe already running. A started local chat process invalidates the Host cache on success, failure, timeout, or cancellation; the renderer then makes an immediate non-forced read. If invalidation occurs during a probe, the Host completes one subsequent probe before publishing the cache. When Auto's renderer snapshot contains no eligible local provider, sending performs one forced Host refresh and selects synchronously from that returned snapshot before reporting no provider; it does not wait for a later React render. After any Host-proven safe local runtime failure, the renderer also forces one provider refresh before choosing the next unattempted fallback, retaining the last verified snapshot only when that refresh itself fails. No refresh path fabricates, interpolates, decrements, or otherwise infers percentage, reset, plan, or model values.

The usage dashboard keeps its header, refresh summary, and footer reachable while provider cards scroll inside the viewport. Card names, verified plan/model metadata, and statuses wrap instead of truncating with ellipses. Reset schedules use one shared human-readable structure across providers: quota window, short month and day, local clock time, and the real IANA timezone. An exact absolute reset timestamp may be localized into that structure; an incomplete provider label remains verbatim rather than having a year or timezone inferred. Missing-quota cards show a short explanation by telemetry kind while preserving the provider's full factual reason as a tooltip; compact copy must not turn unavailable telemetry into an inferred value.

Every chat defaults to persistent `providerMode: auto`. Settings persists one explicit top-to-bottom Automatic fallback priority, independent of the provider catalog's popularity/navigation order. That ranking is a device-wide preference held outside any window's UUID-namespaced workspace snapshot, so changing it in one native window reroutes Auto in every other open window immediately and after restart. A workspace snapshot written before the preference moved is migrated once, and a snapshot that still holds the default ranking never overwrites an explicit device-wide choice. Auto chooses the first connected provider in that priority with a tested chat runner and exact usage below 100%; ranking wins even when a lower-ranked provider has more remaining capacity. A provider with unknown usage is considered, in priority order, only when no connected provider has verified remaining capacity, so unavailable telemetry is never treated as full or empty. Selecting Claude or Codex explicitly changes the chat to fixed mode. Auto Context does not change this choice. Runtime fallback is a separate preference: when enabled, it selects the next eligible, unattempted provider through the same priority only when the Host reports `safeToRetry` and no tool, command, file, or unknown activity occurred. A safe one-turn fallback does not replace a chat's fixed preferred provider.

Every local or SSH execution carries a stable workspace key derived from the native workspace and conversation identity. Before the provider starts, the Host creates or reuses that conversation's `ensync/chat-…` Git worktree and acquires the workspace-keyed write lease shared by every Host process targeting that exact worktree. The provider receives only that protected worktree as its working directory, plus an isolation instruction that forbids mutating another checkout even when older context names the canonical path. Automatic fallback keeps the same workspace key and branch. The canonical selected path remains the project identity, while Git before/after continuation checks and visible workspace metadata use the protected worktree. New worktree creation fails closed without Git or an initial commit. If the shared checkout is dirty, a temporary-index snapshot seeds the protected worktree and is exposed there as uncommitted state without modifying the shared index, checkout, branch, or history; existing conversation worktrees resume their own state. Different conversation worktrees in one repository run concurrently; only duplicate runs targeting the same workspace serialize.

Every runnable provider records exactly one verified containment level in the same catalog-wide capability contract: `os_sandbox` when the CLI offers OS-enforced write restriction the Host can pin per run, `permission_config` when the CLI offers machine-configurable permission rules the Host can pin per run with any residual gap stated factually, or `prompt_only` when `cwd` plus the isolation instruction is all the CLI supports. A provider without a recorded containment level is refused as runnable. Codex's local `exec` and `exec resume` runs pin the OS sandbox in workspace-write mode with `writable_roots` scoped to the protected worktree (`exec resume` rejects `--sandbox` at argv-parse time, so resumed turns instead pin `-c sandbox_mode="workspace-write"` plus the same `writable_roots` override); Codex live-turn/steer runs and every SSH execution remain prompt-plus-`cwd` only — the app-server `sandboxPolicy` field is unverified under the runner's non-experimental handshake and `remoteChatArguments` carries no containment flags — pending first-party verification. Claude Code pins per-run `--settings` deny rules covering `Write`/`Edit`/`NotebookEdit` of the canonical checkout only, not every path outside the worktree; its `Bash` tool is not file-rule constrained, and `-p` print mode silently ignores invalid settings instead of failing closed. Factory Droid pins one risk-tiered `autonomyLevel` (`medium`) plus `interactionMode: auto` on its `droid.initialize_session` or `droid.update_session_settings` call; that tier permits ordinary local build, test, and git work rather than confining writes to the protected worktree, and Droid's own schema declares `autonomyLevel` as `.optional().catch(void 0)`, so an unrecognised value is discarded silently instead of rejected. The runner therefore treats the request as unproven and refuses to send the prompt unless the CLI echoes the pinned level back in its effective settings, failing closed with `provider_containment_unverified` before any turn starts. Prompt confinement by itself is advisory — a strong nudge to a cooperative model, not a security boundary — and Ensync never presents it as enforcement.

Local chat requests may include path-only file attachments explicitly selected or dropped by the user. The Host accepts no more than 64, resolves each to an existing regular file before provider discovery or execution, deduplicates canonical paths, and rejects missing, relative, directory, or inaccessible values. The UI has no MIME/extension allowlist: all regular files remain explicit prompt references. Codex additionally receives GIF/JPEG/PNG/WebP paths through `--image` on both new and resumed runs; attachment paths are masked in the displayed CLI command. Attachments stay with the exact queued turn and are reused only by the same safe local fallback loop.

Local and SSH chats start as opaque, idempotent Host-owned jobs through `POST /api/chat/jobs`; renderers subscribe to bounded sequenced NDJSON through the job stream. A renderer disconnect only removes that subscriber and never cancels the provider process. The workspace checkpoints the job ID before execution and advances its persisted cursor only for non-terminal events, so a replacement renderer can replay missing CLI-visible events and the terminal result exactly once without replaying the prompt. The native app connects to an authenticated detached Host through a user-only rendezvous record and renewable shell lease, allowing normal app quit/reopen to reclaim active jobs. Its checksummed journal excludes prompts and raw provider streams while retaining request hashes, redacted bounded public events, and terminal results; a later Host process can therefore return a completed result without duplicate execution. A journaled job that was still running when the Host actually died becomes non-retryable `host_job_orphaned`, never replayed. Only explicit Stop calls the job cancellation route. If no retained job exists, the renderer falls back to reconciliation-required state instead of guessing completion. Provider-authored progress is a first-class sequenced `note` event: Codex exposes only authoritative completed `agentMessage` items whose phase is `commentary`, while Claude exposes assistant text only when the same streamed message starts tool work; text-only final answers and all thinking/reasoning blocks are excluded. These redacted notes appear directly in the conversation while the run is active and remain in the collapsible execution panel afterward. The execution panel separately shows the real executable/arguments and verified cwd and explicitly says hidden model reasoning is unavailable. Common credential shapes are redacted line-by-line before leaving the Host; redaction is labeled and never changes safe-fallback activity analysis, which continues to inspect the complete internal structured stream. The final parsed chat result still contains no raw stdout/stderr. Browser parsing handles arbitrary network chunk boundaries and caps individual events; the Electron protocol proxy forwards the response body without buffering. SSH execution still buffers its remote bridge envelope, so the panel reports that exact live remote output is unavailable instead of simulating it; it retains honest start/success/failure notices. A safe fallback appends the first failure and the next provider's real start/output to the same per-turn log under a new job ID.

Every chat error exposes `safeToRetry`. Provider-unavailable and subscription-authentication preflight failures are safe because no CLI run started. Claude's exit-code failure is also a pre-activity proof only when stderr is empty and the captured stream is complete and contains exclusively `init` plus `hook_started`/`hook_response` events identified as `SessionStart`; any other hook, assistant/user/tool event, unknown event, stderr diagnostic, or truncated capture makes it non-retryable. A quota/rate-limit/capacity failure is safe only when a complete structured CLI event stream ends in a terminal provider failure and every preceding event is a known non-mutating lifecycle, reasoning, or agent-text event. Tool, command, file, or unknown work items deny retry. Timeouts, malformed/incomplete output, missing completion, output-limit failures, and failures after any activity are never safe to replay. The UI additionally accepts only the Host's explicit provider preflight codes, including `provider_startup_failed`, or `provider_quota`; it does not turn a generic boolean or unknown error into replay authority.

If automatic fallback is enabled and a provider reports an exact 100% used window before a run, Ensync may route directly to another connected supported provider whose known usage is below 100% or whose provider does not report a percentage. Otherwise it attempts the selected provider and uses the existing `safeToRetry` contract before any fallback. A safe quota handoff advances through the saved Automatic fallback ranking without repeating a provider; if another destination also returns a safe proof, Ensync may continue to the next eligible runner rather than stopping after one switch.

Every actual fallback compiles the provider-neutral continuity capsule even when the optional Auto Context toggle is off. The destination receives the focused project's verified execution directory, prior transcript or a synchronized destination session, relevant `.relay` and instruction-file names, available Host-verified Git state, prior continuation state, current request, provider-neutral Model size, and the unchanged local, Sync-paired, or SSH target. The Sync-paired target uses only project and machine facts verified by the selected Host; the SSH label uses the probe's canonical remote project path when available. A fallback response stores structured continuation and attempt metadata so a later provider does not lose the handoff.

Retained local Codex jobs use the subscription-authenticated Codex app-server protocol so the exact active thread/turn can accept `turn/steer`. The initial and steered prompts remain on one provider turn and one Host job; steering never starts a parallel agent, changes provider/target, triggers fallback, or creates a second replayable mutation. The renderer offers live steering only after the Host reports that the provider process started; a retained job may still be in provider preflight or protected-workspace setup and is not yet steerable. The Host rejects interactive app-server approval/input requests it cannot safely review, redacts CLI-visible command output, and keeps Stop bound to that exact process. A protocol rejection with a mismatched/finished active turn is proof the message was not delivered and silently leaves it in FIFO for the successful predecessor's normal automatic release; a transport timeout or malformed/incomplete steering response is ambiguous and must not be resent. User-visible Codex output joins ordered `final_answer` agent-message items, deduplicates repeated item IDs, excludes `commentary`, and falls back to the last unphased message only for legacy provider compatibility.

Same-chat queued prompts snapshot routing intent at enqueue: Auto versus fixed provider, the fixed preference, size tier, fallback enabled/order, Auto Context setting, project identity/path, and exact target key. This prevents later selector changes from silently rewriting already-visible work. At execution, Ensync rechecks current provider availability/usage on that exact verified target and compiles only the completed transcript before the queued turn. A later queued prompt is never exposed to an earlier CLI unless the user explicitly chooses **Push now** for the FIFO head and Ensync verifies that its predecessor, project, target, provider, and retained Host job are that exact still-active local Codex turn. Confirmed steering rebases only the immediate FIFO successor; all other later prompts remain hidden from the active CLI.
