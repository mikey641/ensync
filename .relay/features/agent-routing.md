# Agent routing and usage

Ensync's shared task is provider-neutral. A handoff keeps the same conversation, canonical project, `.relay` feature memory and plan, root `CLAUDE.md` and `AGENTS.md` adapters, and host-verified Git branch/status. Vendor session IDs remain provider-specific below the Ensync task identity, and terminal/runtime state is preserved only when Ensync Host can verify it.

The provider catalog uses a deterministic mainstream-recognition navigation heuristic rather than measured market share: Codex, Claude Code, GitHub Copilot CLI, Cursor Agent, Google Antigravity, Google Jules, Kimi Code, Kiro CLI, Junie CLI, GitLab Duo CLI, Warp Oz, Factory Droid, Amp, Augment Auggie, Qoder CLI, CodeBuddy Code, then the separate local Ollama fallback. Only Claude Code and Codex currently have tested structured Ensync Host chat runners, so they are the only providers eligible for automatic fallback. Every other provider is explicitly discovery-only until it has a tested event parser, subscription-auth guard, session adapter, billing/overage guard, and no-activity retry proof. Jules is a cloud-session agent rather than a local worktree subprocess, and Ollama is local rather than subscription-backed.

Gemini CLI is not in the consumer subscription route. Google stopped Gemini CLI requests for the consumer Individual, Google AI Pro, and Google AI Ultra tiers on June 18, 2026; Antigravity is the current local Google subscription CLI and Jules is the Google cloud-session agent. Qwen Code's current Coding Plan, Mistral Vibe, Aider, OpenCode, Cline, Continue, Goose, OpenHands, and other API-key-backed shells are not subscription-account providers in this catalog. CodeRabbit is review-specific rather than a general coding agent. Ensync must never repurpose one vendor's subscription credentials for another CLI.

Never replay a task on another agent after a mutating tool call. Preserve the transcript and shared project context during safe handoff.

Usage telemetry has an explicit kind: `subscription_quota`, `session_only`, `local_runtime`, or `unavailable`. It records plan, model, source, percentage, reset time, details, and last check only when the CLI reports those values. Ensync does not estimate subscription usage or turn local hardware state into a made-up percentage. Codex uses the official local app-server `account/rateLimits/read` and `model/list` methods after an authenticated ChatGPT login. Claude runs its documented local `/usage` command in safe, tool-free, non-persisted structured mode and accepts the result only when the CLI proves zero API duration, zero model turns, zero tokens, and zero cost. Claude Code 2.1.223 reports its all-model weekly reset as an exact localized schedule such as `Aug 9 at 1am (Asia/Jerusalem)`, but omits the year and an absolute timestamp; Ensync preserves that version-gated label and window for display while keeping `resetAt: null` instead of deriving a calendar date. Unsupported versions or formats keep the label null with a factual reason. For provider routing, Ensync takes the greatest exact provider-wide percentage across Codex quota windows or Claude's current-session and all-model weekly windows; model-specific Claude limits remain informational and do not replace the provider-wide figure. Ollama runs the non-generative `ollama list` and `ollama ps` commands and reports the exact installed/loaded model counts plus its actual model catalog; it never claims a subscription quota. Exact per-run token counts are aggregated by provider/model only when returned by a completed CLI process; unavailable fields stay blank with a reason.

Provider status updates automatically without making every native window launch duplicate CLI probes. Visible renderers request the non-forced `/api/providers` view once per minute and immediately when their window regains focus or visibility. Hidden windows slow to five minutes; Host failures use exponential retry backoff capped at five minutes. The single Host owns a 60-second cache and one shared in-flight refresh, so simultaneous window reads receive the same real probe. Manual Refresh remains an explicit forced check but joins any probe already running. A started local chat process invalidates the Host cache on success, failure, timeout, or cancellation; the renderer then makes an immediate non-forced read. If invalidation occurs during a probe, the Host completes one subsequent probe before publishing the cache. No refresh path fabricates, interpolates, decrements, or otherwise infers percentage, reset, plan, or model values.

The usage dashboard keeps its header, refresh summary, and footer reachable while provider cards scroll inside the viewport. Card names, verified plan/model metadata, and statuses wrap instead of truncating with ellipses. Missing-quota cards show a short explanation by telemetry kind while preserving the provider's full factual reason as a tooltip; compact copy must not turn unavailable telemetry into an inferred value.

Every chat defaults to persistent `providerMode: auto`. Settings persists one explicit top-to-bottom Automatic fallback priority, independent of the provider catalog's popularity/navigation order. Auto chooses the first connected provider in that priority with a tested chat runner and exact usage below 100%; ranking wins even when a lower-ranked provider has more remaining capacity. A provider with unknown usage is considered, in priority order, only when no connected provider has verified remaining capacity, so unavailable telemetry is never treated as full or empty. Selecting Claude or Codex explicitly changes the chat to fixed mode. Auto Context does not change this choice. Runtime fallback is a separate preference: when enabled, it selects the next eligible, unattempted provider through the same priority only when the Host reports `safeToRetry` and no tool, command, file, or unknown activity occurred. A safe one-turn fallback does not replace a chat's fixed preferred provider.

A user Stop is `run_cancelled` (HTTP 499) with `safeToRetry: false`. It exits the routing loop immediately and can never trigger automatic fallback, even when a provider later emits quota-looking output. Renderer disconnect propagates through the Host to the exact local provider or OpenSSH child with bounded graceful-then-force termination; cancellation is distinct from success, failure, timeout, and quota telemetry.

An unexpected provider termination reports its real integer exit code, its validated operating-system signal, or an explicit absence of a reported exit code. Ensync must never render `code null`. Signal and missing-code failures remain non-retryable and reconciliation-required because partial provider activity may exist; clearer diagnostics do not weaken the safe fallback boundary.

Every conversation header has separate, always-visible Provider and Model size selectors with the same portal, collision, and keyboard-accessible interaction pattern. Model size never exposes or invents raw model IDs: `Provider default` is first and omits both model and effort flags; `Small`, `Medium`, `Large`, and `XL` map exactly to `low`, `medium`, `high`, and `max` effort over the selected provider's own default model. The persistent chat keeps `model: null` and stores only the friendly `sizeTier`. Size is independent of `providerMode`, Auto Context, and Automatic fallback, so it follows Auto routing or a fixed Codex/Claude choice and is preserved on a safe fallback; changing providers does not clear it. The local and SSH runners validate the strict effort enum, apply Codex `-c model_reasoning_effort="<effort>"` at the correct `exec` or `exec resume` scope, and apply Claude `--effort <effort>` to new or resumed runs. Public run metadata retains the requested effort, and completed message metadata shows the friendly tier beside the exact CLI-reported model while leaving unreported models explicit.

Ensync Host exposes loopback-only provider discovery at `/api/providers`, per-provider status, connect, and update routes, and `/api/usage`. Discovery runs the installed CLI's own version and authentication-status commands with model API-key environment variables removed. A missing or unsupported value is `null` with a reason; the host never creates plan names, percentages, models, reset windows, or newer-version claims. Connect routes can only launch fixed, allowlisted provider login commands in a native terminal. Update routes have the same fixed-command boundary: the browser cannot choose an executable or arguments, preview mode is non-mutating, and an actual launch is refused while Ensync Host owns any running agent job.

Codex and Claude Code are the first verified self-update providers. Ensync launches the installed executable with exactly `update`, shows the precise installed version reported before launch, and asks the user to refresh after the terminal command finishes; the provider CLI remains authoritative for install method, release channel, update availability, and result. All other providers keep their official installation/update guide and a factual reason until a provider-owned cross-platform update command is verified. Ensync does not substitute guessed npm, Homebrew, WinGet, or OS package-manager commands.

Provider discovery and setup are intentionally specific:

- Claude Code uses `claude auth status --json`, a verified zero-cost structured `/usage` probe, and `claude auth login`.
- Anthropic's June 15, 2026 update says its proposed separate Agent SDK credit change was paused; `claude -p` currently continues to draw from the normal subscription usage limits. Reverify this billing contract before each public runner release because Anthropic says it will announce a future change before it takes effect.
- Codex uses `codex login status` for authentication, `codex login` for setup, and the initialized local stdio app-server for real ChatGPT plan, quota-window, reset, default-model, and model-catalog data.
- Kimi Code uses `kimi --version` and the exact device-OAuth command `kimi login`. The maintained CLI supports persistent ACP sessions, but Ensync keeps it discovery-only until a tested ACP adapter and a verified quota probe are present. Kimi Extra Usage is optional pay-as-you-go overage and must never be treated as subscription capacity or used by automatic fallback without explicit opt-in.
- Google Antigravity uses `agy --version`; bare `agy` performs first-run Google browser sign-in. `/usage`, `/quota`, and `/credits` are interactive panels, so Ensync keeps the percentage unknown until a stable adapter exists. Purchased-credit overages must be set to Never before any future routing.
- Google Jules uses `jules version` and `jules login`. It dispatches Google AI Pro/Ultra-backed cloud sessions rather than operating as a local worktree subprocess, so it requires a separate execution-topology adapter.
- GitHub Copilot CLI is an autonomous coding agent, not a command-suggestion utility. Ensync verifies its stored signed-in account through the official SDK-compatible headless stdio protocol: send `connect`, require protocol v2 or v3, then call `auth.getStatus`. This creates no session, sends no prompt, and returns the explicit `user` authentication type and account login. The probe removes `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, and `GITHUB_TOKEN`, rejects token/generic `gh` auth as account proof, never reads credentials, and is bounded for time and response size. Account quota stays unavailable because this response contains no allowance/reset data. `discovery_only` now describes runner readiness only; execution and fallback remain disabled until a tested JSONL or ACP runner, subscription-entitlement guard, session adapter, additional-AI-credit protection, and no-activity retry proof exist.
- Cursor prefers the official `agent` entrypoint and falls back to the backward-compatible `cursor-agent` alias. It uses `status` and `login` with API-key environment authentication removed.
- Kiro uses `kiro-cli whoami --format json` and `kiro-cli login`, with `KIRO_API_KEY` removed so the probe cannot silently select usage-billed key authentication.
- Qoder uses its documented `qodercli login` browser flow. Subscription credits are dashboard-only, and optional account-token/BYOK environment overrides are removed.
- CodeBuddy uses bare `codebuddy` (or `cbc`) for browser onboarding. Its account dashboard is authoritative for subscription credits; API-key headless mode is excluded.
- Factory Droid uses bare `droid` for browser onboarding. Interactive `/limits` data, Droid Core, and Extra Usage remain unparsed, and the documented API-key headless route is excluded.
- Augment Auggie uses `auggie login`; account billing and per-run credits stay unknown until a stable provider-wide quota contract is tested.
- Amp uses `amp login`; `amp usage` exposes account balance, but paid credits are not subscription capacity and are excluded from routing.
- GitLab Duo uses the standalone `duo` executable for discovery, but subscription setup depends on existing `glab` OAuth and an eligible namespace. Ensync does not collect GitLab PATs or infer a quota percentage from the dashboard.
- Warp Oz uses `oz login` for browser account authentication. `WARP_API_KEY` is removed in subscription mode, and neither local nor cloud execution is enabled until credit and overage behavior is guarded.
- Junie uses `junie --version`. JetBrains Account sign-in happens in the interactive welcome screen, so Ensync can open `junie` but cannot non-interactively claim an authenticated subscription. Junie's `/usage` is current-session cost/token/model data rather than an account quota, so the catalog marks it `session_only` until a tested runner can collect it after real runs.
- Ollama uses `ollama -v`, `ollama list`, and `ollama ps`. It is a local runtime with no subscription login or subscription-usage percentage; Ensync reports only exact local model inventory/load state and does not yet claim chat execution support.

The connection wizard scopes terminal commands and success/error feedback to the selected provider. A command returned for one provider must never remain visible after another provider is selected. It shows the installed CLI's exact version, exposes **Update agent** only for verified self-update providers, disables that action while an agent run is active, and explains why update automation is unavailable for guide-only providers. Every provider card exposes a prominent official vendor installation/update link; these links are separate from login and were verified reachable when added.

Local chat execution uses `POST /api/chat/run`. The host currently supports authenticated subscription logins for Codex and Claude Code only, validates and canonicalizes an absolute non-root project directory plus any model/effort override, sends prompts over stdin, and scrubs API-key and alternate paid-provider environment variables. Production chat runs use a 15-minute inactivity watchdog refreshed only by the real process lifecycle or stdout/stderr, plus an independent two-hour hard ceiling, so productive long-running coding work is not killed by the former five-minute absolute timer. Either timeout uses bounded graceful-then-force termination and reports whether inactivity or the hard ceiling fired. Timeouts remain non-retryable and reconciliation-required because partial mutations may exist. The Host parses only each CLI's machine-readable output; a missing final response, malformed output, timeout, failed command, unsupported provider, or non-subscription login is an explicit error. Per-run token counts are exposed only when reported by the CLI and stay separate from subscription-window usage.

Local chat requests may include path-only file attachments explicitly dropped by the user. The Host accepts no more than 64, resolves each to an existing regular file before provider discovery or execution, deduplicates canonical paths, and rejects missing, relative, directory, or inaccessible values. The UI has no MIME/extension allowlist: all regular files remain explicit prompt references. Codex additionally receives GIF/JPEG/PNG/WebP paths through `--image` on both new and resumed runs; attachment paths are masked in the displayed CLI command. Attachments stay with the exact queued turn and are reused only by the same safe local fallback loop.

Local and SSH chats start as opaque, idempotent Host-owned jobs through `POST /api/chat/jobs`; renderers subscribe to bounded sequenced NDJSON through the job stream. A renderer disconnect only removes that subscriber and never cancels the provider process. The workspace checkpoints the job ID before execution and advances its persisted cursor only for non-terminal events, so a replacement renderer can replay missing CLI-visible events and the terminal result exactly once without replaying the prompt. The native app connects to an authenticated detached Host through a user-only rendezvous record and renewable shell lease, allowing normal app quit/reopen to reclaim active jobs. Its checksummed journal excludes prompts and raw provider streams while retaining request hashes, redacted bounded public events, and terminal results; a later Host process can therefore return a completed result without duplicate execution. A journaled job that was still running when the Host actually died becomes non-retryable `host_job_orphaned`, never replayed. Only explicit Stop calls the job cancellation route. If no retained job exists, the renderer falls back to reconciliation-required state instead of guessing completion. The execution panel shows the real executable/arguments and verified cwd, stays open while a run is active, remains collapsible afterward, and explicitly says hidden model reasoning is unavailable. Common credential shapes are redacted line-by-line before leaving the Host; redaction is labeled and never changes safe-fallback activity analysis, which continues to inspect the complete internal structured stream. The final parsed chat result still contains no raw stdout/stderr. Browser parsing handles arbitrary network chunk boundaries and caps individual events; the Electron protocol proxy forwards the response body without buffering. SSH execution still buffers its remote bridge envelope, so the panel reports that exact live remote output is unavailable instead of simulating it; it retains honest start/success/failure notices. A safe fallback appends the first failure and the next provider's real start/output to the same per-turn log under a new job ID.

Every chat error exposes `safeToRetry`. Provider-unavailable and subscription-authentication preflight failures are safe because no CLI run started. A quota/rate-limit/capacity failure is safe only when a complete structured CLI event stream ends in a terminal provider failure and every preceding event is a known non-mutating lifecycle, reasoning, or agent-text event. Tool, command, file, or unknown work items deny retry. Timeouts, malformed/incomplete output, missing completion, output-limit failures, and failures after any activity are never safe to replay. The UI additionally accepts only the Host's explicit provider preflight codes or `provider_quota`; it does not turn a generic boolean or unknown error into replay authority.

If automatic fallback is enabled and a provider reports an exact 100% used window before a run, Ensync may route directly to another connected supported provider whose known usage is below 100% or whose provider does not report a percentage. Otherwise it attempts the selected provider and uses the existing `safeToRetry` contract before any fallback. A safe quota handoff advances through the saved Automatic fallback ranking without repeating a provider; if another destination also returns a safe proof, Ensync may continue to the next eligible runner rather than stopping after one switch.

Every actual fallback compiles the provider-neutral continuity capsule even when the optional Auto Context toggle is off. The destination receives the focused project's verified execution directory, prior transcript or a synchronized destination session, relevant `.relay` and instruction-file names, available Host-verified Git state, prior continuation state, current request, provider-neutral Model size, and the unchanged local or SSH target. The SSH label uses the probe's canonical remote project path when available. A fallback response stores structured continuation and attempt metadata so a later provider does not lose the handoff.

Retained local Codex jobs use the subscription-authenticated Codex app-server protocol so the exact active thread/turn can accept `turn/steer`. The initial and steered prompts remain on one provider turn and one Host job; steering never starts a parallel agent, changes provider/target, triggers fallback, or creates a second replayable mutation. The Host rejects interactive app-server approval/input requests it cannot safely review, redacts CLI-visible command output, and keeps Stop bound to that exact process. A protocol rejection with a mismatched/finished active turn is proof the message was not delivered and may fall back to FIFO; a transport timeout or malformed/incomplete steering response is ambiguous and must not be resent. User-visible Codex output joins ordered `final_answer` agent-message items, deduplicates repeated item IDs, excludes `commentary`, and falls back to the last unphased message only for legacy provider compatibility.

Same-chat queued prompts snapshot routing intent at enqueue: Auto versus fixed provider, the fixed preference, size tier, fallback enabled/order, Auto Context setting, project identity/path, and exact target key. This prevents later selector changes from silently rewriting already-visible work. At execution, Ensync rechecks current provider availability/usage on that exact verified target and compiles only the completed transcript before the queued turn. A later queued prompt is never exposed to an earlier CLI. Different chats remain concurrent, while one chat has at most one active provider job; eligible local Codex corrections may join that active turn, and every other later prompt stays strict FIFO.
