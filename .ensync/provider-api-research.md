# Provider API and automation research

This is a dated research ledger, not a promise that an interface is runnable. The durable policy lives in [`project.md`](project.md), the adapter decisions live in [`features/agent-routing.md`](features/agent-routing.md), and the executable provider catalog remains authoritative for current product status.

“API” includes a vendor's supported SDK, local protocol, headless CLI, or REST service. Finding one proves only technical reachability. Before Ensync enables execution or fallback, it must separately prove subscription/account eligibility, paid-overage behavior, stable machine-readable events, session semantics, mutation evidence, cancellation, and equal macOS/Windows behavior.

## Catalog-wide review contract

Every provider-facing change must record one of `supported`, `discovery_only`, or `unavailable` for every catalog provider across the affected capabilities:

1. Executable discovery, official installation, version, and update path.
2. Account identity, login method, credential precedence, and entitlement evidence.
3. Included subscription allowance versus API billing, add-ons, top-ups, or automatic overage.
4. Machine-readable request/response transport, protocol/schema version, output limits, and failure framing.
5. Session create, resume, fork, steer/queue, and provider-session invalidation.
6. Tool calls, approvals, mutation evidence, cancellation, timeouts, and safe-to-retry proof.
7. Provider-wide quota/reset telemetry without consuming a model turn.
8. Local versus cloud execution, exact project/branch/worktree identity, and remote SSH constraints.
9. macOS and Windows command, credential-store, process-tree, sandbox, and updater behavior.

Unknown capability remains explicit and disabled. An API key is never treated as proof that a request will use included subscription capacity.

## Automatic landing resolver review (verified 2026-09-04)

This capability was reviewed separately from ordinary chat because it can mutate a temporary Git integration worktree and publish the resulting merge. Git's own [`checkout` documentation](https://git-scm.com/docs/git-checkout) defines `--ours` and `--theirs` as selecting one unmerged index stage for a path; it does not claim to preserve the intent of both edits. Ensync therefore forbids whole-side fallback at every attempt count. A failed resolver is discarded with its temporary worktree and the immutable saved SHA stays queued.

- **Supported:** Codex, Claude Code, and Factory Droid. All three already have subscription-authenticated structured local runners and the containment contract required for automatic landing. The resolver retains the current account/provider default model and requests `max` effort. OpenAI's current [GPT-6 Astra model documentation](https://developers.openai.com/api/docs/models/gpt-6-astra) includes `max` among the supported reasoning levels. Claude Code documents [`--effort` and `max`](https://code.claude.com/docs/en/model-config), calls `max` its deepest reasoning level, and explicitly handles a model or organization cap by falling back to the highest supported level. Factory documents per-model [`reasoningEffort`](https://docs.factory.ai/models), while its [SDK model discovery contract](https://docs.factory.ai/sdk/python#models) says availability and supported/default effort vary by account, organization, feature flags, region, and project settings.
- **Discovery-only:** GitHub Copilot CLI, Cursor Agent, Google Antigravity, Google Jules, Kimi Code, Kiro CLI, Junie CLI, GitLab Duo CLI, Warp Oz, Amp, Augment Auggie, Qoder CLI, and CodeBuddy Code. Their existing catalog blockers also prevent automatic landing; none is silently eligible merely because it later becomes installed or authenticated.
- **Unavailable:** Ollama local model discovery has no permissioned coding-agent runner and cannot resolve a repository conflict.

There is no honest catalog-wide “strongest model” identifier. Claude's default varies by subscription/account, Factory model availability is account- and organization-specific, and Codex exposes an account model catalog. Hard-coding one vendor's current flagship would be stale or unavailable for other accounts. Ensync instead records one explicit landing profile per provider, uses that provider's account-selected model at its deepest verified effort, starts with the originating provider, rotates across all other eligible providers on subsequent attempts, and retries on a durable backoff until a resolution passes. If a future provider is promoted to chat execution, tests require its landing capability to be classified separately before it can join this rotation.

The online merge-queue pattern supports the same fail-closed rule: [GitHub merge queues](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/merging-a-pull-request-with-a-merge-queue) remove an entry when required checks fail or branch protection cannot resolve it; they do not choose one side of a conflict. The current Ensync repository cannot rely on that hosted feature because GitHub documents private-repository merge queues for organization-owned Enterprise Cloud repositories, so the Host's local queue remains the primary control.

## No-card account walks and headless smoke tests (verified 2026-09-07)

A headless smoke test here proves only that an installed, freshly authenticated CLI can complete a non-mutating `pong` turn without a card on file. It is not execution permission: each provider keeps its catalog blocker until subscription eligibility, no-overage, mutation-evidence, and session contracts are machine-verified.

- **Verified headless `pong`** (non-mutating smoke prompt):
  - Cursor Agent — account `mikey641@gmail.com` (Hobby); headless JSON smoke returned `pong`.
  - Kiro CLI — account `mikey641@gmail.com` (SocialGoogle), with 0.03 credits reported; headless `pong`.
  - Qoder CLI — account `mikey641`; headless `pong`.
  - Google Antigravity — account `mikey641` via Google OAuth (authorization code redeemed through a pseudo-terminal); headless `pong`.
  - GitHub Copilot CLI — account `mikey641`, with 2.19 AI credits reported by Copilot; headless `pong`.
- **Account created, not headless-verified:** CodeBuddy Code — account created, but the first-run provider selector required a manual keypress in the TUI, so no headless turn was verified.
- **Connected but blocked:** Amp — `mikey641@gmail.com` authenticated with a $0 credit balance; a headless Amp run blocks indefinitely, so no turn was verified.
- **Provider-side login failure:** Kimi Code — device login returned a server error across three attempts; no account was created.
- **Credential precedence confirmed:**
  - Junie CLI stores no local token after its JetBrains-account onboarding. Headless mode requires `--auth` with a usage-based key from `junie.jetbrains.com/cli`, while the interactive welcome screen offers "Continue with JetBrains account".   - GitLab Duo CLI signs in by saving a Personal Access Token with `api` scope into `duo config` (first-run `duo` setup, `duo config edit`, or the `--gitlab-auth-token`/`GITLAB_TOKEN` inputs). ## Current conclusions

### Active-turn lifetime finding (verified 2026-08-07)

- Codex non-interactive `codex exec --json`, which is Ensync's current runner, documents starting and resuming sessions but no way for a new controller to attach to an already-running `exec` stream. App Server now documents per-connection subscriptions, a 30-minute no-subscriber/no-activity unload grace, an experimental unsupported WebSocket listener, and a local Unix-socket transport. Those surfaces make a separately supervised, reconnectable Codex adapter plausible, but the documentation does not establish production support or complete missed-event replay after a controller loss; it is not yet evidence that the current runner can survive Host death.
- Claude Code print mode similarly documents stream-JSON and session `--resume`, but not reattaching a new `claude -p` controller to an active print-mode stream. Claude's separate Agent View now documents background sessions parented to a provider-owned supervisor and reconnection after supervisor restart. Ensync has not verified that interactive/background surface as a stable structured third-party runner, and using it for one provider would not establish the catalog-wide guarantee.
- Ensync therefore keeps its detached Host alive across renderer and shell crashes and reattaches the UI to Host-owned jobs for every supported provider. If that Host itself actually dies, the current enabled runners permit safe session continuation only after reconciliation; they do not justify replaying or claiming completion of the active tool run. Provider-native supervisors remain future adapter candidates, while the shared guarantee requires an Ensync-owned durable provider-worker boundary with exact event reconciliation.

### Provider progress-note streaming finding (verified 2026-08-07)

- Codex CLI 0.146.0's generated App Server schema and current first-party App Server documentation expose `agentMessage` items with `commentary` or `final_answer` phases plus authoritative `item/completed` notifications. Ensync marks local Codex progress notes `supported` by forwarding only completed `commentary` text; raw reasoning events remain excluded.
- Claude Code 2.1.223 and its current CLI documentation expose verbose stream-JSON as ordered assistant messages followed by a terminal result. Because that protocol does not distinguish commentary from the final answer, Ensync marks local Claude progress notes `supported` only for assistant text in a message that also starts tool work; text-only final messages and thinking blocks remain excluded.
- Catalog-wide result for this capability at the 2026-08-07 measurement: Codex and Claude local progress notes were `supported`; other providers were not yet promoted. Factory Droid was subsequently promoted with its structured runner. Live SSH provider notes remain `unavailable` in the current buffered bridge and must not be simulated.

### Factory Droid /limits telemetry finding (verified 2026-08-10)

Measured against droid 0.191.1 (factoryProtocolVersion 1.154.0) on macOS. Every candidate surface for a non-consuming, machine-readable quota read was checked; none exists, so this capability is `unavailable` rather than untested:

- The interactive TUI's /limits pane fetches `GET /api/billing/limits` from Factory's cloud in-process with the CLI's own stored browser-login auth. The response carries `limits.standard` and `limits.core` buckets (`fiveHour`, `weekly`, `monthly`, each with `usedPercent` and `windowEnd`) plus `extraUsageBalanceCents` and the overage preference — the exact shape a future adapter should expect.
- The exec stream-jsonrpc surface has no usage or billing method anywhere in its request enum, and `droid.list_commands` on a live session returns an empty command list, so slash commands are not interceptable there.
- The `droid daemon` JSON-RPC surface likewise has no billing method, and droid persists no local cache of the limits response under `~/.factory`.
- `droid exec -o json "/limits"` does not open the panel: the text is delivered to the model as an ordinary prompt. One measured probe consumed 15,231 input plus 2,155 output tokens (15,574 Factory credits), so a text-mode probe is quota-consuming and must never run automatically.
- Factory's CLI reference documents /limits, /billing, /cost, and /stats as interactive-only with no non-interactive equivalent, flag, or documented account-limits REST endpoint for browser-login accounts.
- Calling `/api/billing/limits` directly would require reading `~/.factory/auth.v2.loginkeychain`, which Ensync's credential policy forbids; driving the TUI through a pseudo-terminal fails the stable machine-readable transport rule.

Droid's exec runner still reports quota exhaustion exactly through the `model_usage_exhausted` turn reason, which Ensync already maps to a provider-quota error. Re-run this check when Factory ships a documented non-interactive limits surface.

### Claude 5-hour session-limit stream finding (verified 2026-09-07)

Captured verbatim from Claude Code 2.1.263 on macOS with the 5-hour session window exhausted (`claude --print --verbose --output-format stream-json`, exit 1, empty stderr). The turn emits exactly four events: `system/init`, a `rate_limit_event` whose `rate_limit_info` has `status: "rejected"` and `rateLimitType: "five_hour"`, a synthetic `assistant` message containing one `text` block that is only the limit line (`is_api_error_message: true`, `error: "rate_limit"`), and a terminal `result` with `is_error: true`, `subtype: "success"`, `terminal_reason: "api_error"`, `api_error_status: 429`, and `result: "You've hit your session limit · resets 4:40am (Asia/Jerusalem)"`. None of these four events is work, so Ensync's `quotaFailureIsSafe` classifies the stream as `provider_quota` / `safeToRetry` (429) and the automatic-fallback continuation moves to the next provider. `host/chat.test.mjs` pins the exact stream so a future CLI change to this shape is caught instead of silently regressing to `cli_failed`.

Claude also names an exhausted per-model window without the shared `usage`/`rate`/`session` vocabulary: `You've reached your Fable limit. Switch to another model, or manage usage credits at claude.ai/settings/usage?from=cc_cli_limit_message, to continue.` Ensync's Claude quota prose additionally accepts the `reached/hit your <window> limit` phrasing, so a per-model limit with the same zero-activity structured proof also classifies as `provider_quota` / `safeToRetry` instead of surfacing as an unretryable `cli_failed`.

### Claude background-task lifetime finding (verified 2026-09-10)

Measured against Claude Code 2.1.267 on macOS with `claude --print --verbose --output-format stream-json`, prompted to start one background task and end the turn:

- Background work is reported as a `system/background_tasks_changed` level (`tasks: [{task_id, task_type, description}]`, replace semantics, emptied before the matching notification) plus `task_started`, `task_progress`, `task_updated`, and `task_notification` (`status` `completed`, `failed`, or `stopped`) edges. Tasks a subagent starts carry `owned_by_subagent: true`. `session_state_changed`, which the Agent SDK 0.3.220 types call the authoritative idle signal, was not emitted.
- Plain print mode (prompt on stdin, stdin closed) waits for a background subagent (`local_agent`): the process stays open, the parent gets a follow-up turn when the subagent reports, one `result` is emitted per turn, and the CLI exits 0 once no subagent remains. A background shell (`local_bash`) is not awaited: it is `stopped` about five seconds after the result and the CLI exits 0.
- With `--input-format stream-json` and stdin left open, the first `result` is emitted immediately, and the CLI opens a follow-up turn (`system/init` within milliseconds of the level emptying) for either a subagent or a shell, then emits another `result`. Closing stdin at the first `result` stops a background shell as plain print mode does; in a 2026-09-10 Ensync chat it also left a background subagent working until it was interrupted ten minutes later, with no parent follow-up turn.
- Each `result.usage` covers only its own turn; `total_cost_usd` is cumulative.

Ensync's retained Claude jobs therefore keep stream-json stdin open while the level lists a subagent (see [`features/provider-questions.md`](features/provider-questions.md)). This measurement covers Claude Code only; other runners' background-work lifetimes were not re-measured.

- Codex remains the reference for an account-authenticated, structured local runner.
- Claude remains technically integrated, but the current third-party OAuth and separate Agent SDK credit terms are a public-release blocker until resolved.
- Factory Droid is now a supported local runner. Copilot, Kimi, Auggie, Qoder, CodeBuddy, Cursor, Kiro, Amp, Antigravity, Junie, and Oz expose useful machine interfaces but retain explicit subscription identity, paid-overage, or complete mutation/cancellation blockers.
- Antigravity has a capable SDK but no verified subscription-safe headless CLI contract; Junie documents headless use through a usage-based token, and its license/balance is read from `/stats`; Qoder and Oz expose account identity (`qodercli status` / `oz whoami`) but no plan-credit percentage; GitLab Duo's headless mode is stateless and auto-approves tools.
- Jules is a cloud-session adapter, and Ollama needs an Ensync-owned agent/tool loop. Neither should be forced into the local subscription subprocess contract.
