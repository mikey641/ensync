# Display preferences

Ensync supports light, dark, and system-following themes. The preference is stored locally, resolved before the application paints, and updated live when the operating-system scheme changes while system mode is selected.

Large text is the default: normal UI content uses 15px type and conversation content uses 18px. A persistent comfortable option uses 14px UI and 16px conversation content. Labels remain at least 13px; only purely illustrative marks may be smaller.

User and agent messages longer than 900 characters or 14 lines expose an accessible per-message collapse control. Messages remain expanded initially, collapse to a bounded inert text preview without changing their stored content, and can be expanded again in place; live provider notes remain outside this transcript-only behavior.

The unread task-finished indicator is also device-local and persistent. Existing workspaces default to the compact green dot, while Settings can instead tint the unread tab or pane header green, or tint and outline the whole unread conversation pane. This changes only presentation: the indicator still represents the exact latest completed agent message and follows the existing chat-scoped read, working, failure, hidden-pane, and relaunch rules. Appearance storage is versioned at `ensync-display-preferences-v2` and migrates both earlier v1 keys so an older open renderer cannot strip the new completion field from the current record.

The agent-alert sound preference is device-wide. Browser mode keeps mode, spoken text, voice, whether a waiting question alerts, and its own spoken words in `ensync-completion-notifications-v1`. The native shell additionally commits the same normalized values to a checksummed `device-preferences-v1.json` primary/staging/backup store under app data. Native startup restores that record before React mounts; when the native record does not exist yet, it migrates the current renderer value once. This preserves an explicit Off, ringtone, or spoken-text choice across renderer storage and origin resets without making alert settings workspace-specific.

One alert setting covers both things worth interrupting someone for: an agent that finished, and an agent that stopped to ask (see Provider questions). They share the mode and the voice so there is one alert to configure, and differ in the only ways that carry the news — separate spoken words, and two chimes shaped differently rather than pitched differently, so which one rang is audible from another room. Question alerts default to on and can be switched off on their own; a stored preference written before they existed loads with them on rather than failing to load, on both the renderer and the native store.

Theme styles use shared semantic surface, border, text, accent, focus, overlay, shadow, and scrollbar tokens. New components must use these variables rather than theme-specific hex colors.

Conversation Markdown renders as structured blocks: paragraphs, ATX headings, fenced code, GitHub tables, ordered and unordered lists with nesting, block quotes, and thematic breaks. Inline Markdown resolves code spans, bold, italic, strikethrough, and links everywhere, not only inside tables. Message text is still never interpreted as HTML — rendering builds React elements from a parsed tree, so no raw-HTML injection path exists. Link destinations are restricted to `http(s)`, `mailto`, anchors, and in-app paths; any other destination, including `javascript:`, renders as literal text rather than an anchor. Unmatched delimiters stay literal, underscores never emphasize inside a word so identifiers such as `snake_case_name` survive, and paragraphs keep their newlines through `pre-wrap`.

Rendered Markdown follows the conversation content scale rather than fixed pixel sizes, so tables, lists, headings, code blocks, and inline code all track the Comfortable/Large preference like ordinary message prose. Table and list text use `--font-content` directly, headings and code blocks derive from it with a multiplier, and inline code is sized in `em` so it matches whichever block contains it. Pinning a pixel font size anywhere in rendered message content is a regression: it previously made tables read several pixels smaller than the prose beside them.

GitHub-style tables become real `<table>` elements with header scope, per-column alignment mapped to logical `start`/`center`/`end`, ragged rows padded or truncated to the header width, and escaped `\|` kept literal. A table ends at the first blank or pipe-less line so following prose is never absorbed, and the scroll container around each table is keyboard focusable.

Conversation text is bidirectional by content rather than by application locale. User drafts, user and agent messages, stored-context previews, and CLI-visible output use HTML `dir="auto"`; multi-line output also uses `unicode-bidi: plaintext` so each Hebrew or English paragraph derives its own base direction while embedded Latin code, paths, commands, numbers, and punctuation retain Unicode bidi ordering. Rendered messages go one step further: each opposite-direction phrase inside a line is wrapped in `<bdi>`, so the punctuation, prices, and counts written around a Hebrew phrase stay where the agent wrote them instead of being reordered into the middle of it. Fixed workspace chrome stays left-to-right, and bidi support must not rewrite stored or copied text with invisible control characters.

Conversation prose renders links instead of raw Markdown. A `[label](target)` reference, a Markdown autolink, and a bare `https` URL become anchors; the label and any unsupported destination stay the exact text the agent wrote. Only `https` targets and absolute local paths (including `file://` URLs) are linkable, so a destination written by an agent can never resolve to a script-bearing scheme. An `https` link opens through the existing external-window policy. A local path opens a file display inside Ensync rather than leaving the conversation: the host reads the absolute path, returns the text with its real byte size, truncates at a fixed cap instead of refusing a large file, and reports a missing path, a folder, or non-text content as an explained status. The viewer can copy the contents and hand the path to the native shell, which still accepts only absolute paths and reveals anything executable in the file manager rather than running it. Where no viewer is wired up, a file link falls back to that native bridge, and browser mode without either keeps the plain `file` href instead of a dead click.

The desktop workspace and public product site share one visual language. The app maps the site's neutral paper/charcoal surfaces, teal status accent, Inter type stack, linked-loop Ensync mark, softly elevated cards, rounded pill controls, user-message bubbles, and circular send action through the semantic display tokens. Both light and dark themes keep this relationship; page-specific site layout must not replace desktop interaction state or accessibility behavior.
