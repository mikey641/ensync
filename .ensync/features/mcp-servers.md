# MCP servers

Ensync keeps one list of Model Context Protocol servers per Host and mirrors it into the native configuration file of every installed catalog provider whose MCP schema is verified, so a server added once is available in Claude Code, Codex, and every other supported CLI without being re-entered. The list is a settings section in Preferences, not a per-conversation control: MCP servers describe tools the person owns, and the Host that runs the providers is the only place that can write their files. The registry lives in the Host's app-data directory as `ensync-mcp-servers-v1.json` (overridable with `ENSYNC_HOST_MCP_REGISTRY_FILE`), holds up to 64 servers, and stores each one in a provider-neutral shape: a name, a transport of `stdio`, `http`, or `sse`, a command with arguments and environment for stdio, or a URL with headers for remote servers, plus an enabled flag. Names are restricted to letters, digits, hyphens, and underscores so they are valid keys in every provider file, including TOML table headers.

Servers a person already configured inside a CLI are adopted automatically instead of being re-entered. When the settings panel loads the list, the Host reads the person's existing MCP definitions from every supported provider with a local file (Claude Code `~/.claude.json`, Codex `$CODEX_HOME/config.toml`, and the `mcpServers` key in Copilot, Cursor, Kimi, Antigravity, Kiro, Qoder, CodeBuddy, Droid, Auggie, Amp, GitLab Duo, and Junie), normalizes them into the same provider-neutral shape, and adds any name that is not already in the registry. Those provider files are discovery sources and are never modified during adoption; the adopted entries are mirrored to every other supported provider in the usual way, while the source provider's own entry is left exactly as the person wrote it. Each adopted registry entry records `adoptedFrom`, and removing an adopted server writes a tombstone keyed by source and name so the next panel load does not silently re-adopt it. Adoption is fully automatic and idempotent; no terminal commands or manual import step are involved.

Sync is catalog-wide and capability-driven. `host/mcp-provider-config.mjs` gives every provider ID an explicit MCP capability with a factual reason: `supported` providers have a first-party-verified user-scope file and schema (Claude Code, Codex, GitHub Copilot CLI, Cursor Agent, Google Antigravity, Kimi Code, Kiro CLI, Junie CLI, GitLab Duo CLI, Factory Droid, Amp, Augment Auggie, Qoder CLI, CodeBuddy Code), while `unavailable` providers have no local MCP file Ensync could write (Google Jules is cloud-only, Warp Oz reads servers from the Warp account or a per-run flag, and Ollama is not an MCP client). A provider is never silently omitted. Each supported entry serializes the neutral shape into that provider's own schema: Claude Code, Copilot, Droid, Auggie, Qoder, CodeBuddy, and GitLab Duo carry a `type` discriminator; Cursor, Kiro, Junie, Amp, and Antigravity infer the transport from the presence of a URL, with Antigravity naming it `serverUrl` and Amp keeping servers under the flat `"amp.mcpServers"` key; Kimi Code marks only SSE entries with `transport`; Codex is TOML with `[mcp_servers.<name>]` tables and `env` or `http_headers` sub-tables. A transport a provider cannot express (SSE on Codex, undocumented SSE on Junie, headers on GitLab Duo) is skipped for that provider and reported by name rather than written in a shape the CLI would reject. Provider paths honor the vendor's own environment overrides (`CODEX_HOME`, `COPILOT_HOME`, `KIMI_CODE_HOME`, `JUNIE_HOME`, `QODER_CONFIG_DIR`, `CODEBUDDY_CONFIG_DIR`, `AMP_SETTINGS_FILE`, `GLAB_CONFIG_DIR`, `XDG_CONFIG_HOME`, `APPDATA` on Windows), and CodeBuddy writes to the first of its three candidate user files that already exists so a new file never shadows servers kept in an older one.

Writes are merges, never overwrites, and they are ledgered. JSON files are parsed, the managed entries are set under the provider's key path, every other key is carried through, and the result is written through a staging file and rename; Codex's TOML is edited line by line so the person's comments and other tables survive. A per-provider sync ledger inside the registry records exactly which server names Ensync wrote into which file, so a later edit, disable, or removal rewrites or deletes only those names. A same-named entry the person configured through the provider itself is never overwritten; it is left untouched and reported as a conflict only when it actually differs from the registry, while an entry Ensync adopted from that provider (or one that already carries the identical server definition) is left in place and reported as satisfied rather than a conflict. A file Ensync cannot parse is reported as an error and never modified. Disabled servers are removed from every provider rather than written with provider-specific disabled flags. Because Claude Code rewrites `~/.claude.json` for itself during a session, provider files are only edited while no Host-owned agent run is active; a change made mid-run is journaled as deferred, retried automatically once the Host is idle, and shown as waiting in the settings panel. Sync runs after every registry change, on Host startup when anything is managed, and on demand from the panel; it never launches a provider to apply configuration and never claims a provider has loaded a server, only that its file now contains it.

The renderer never receives secret values. Environment and header values come back masked, and sending the mask back on an edit keeps the stored value; a new value replaces it. The settings section lists the registry, offers a form and a paste-JSON import that understands the `mcpServers` wrapper published in most server READMEs (including Claude-style `type` and Copilot-style `local` entries), toggles and removes entries with an inline confirmation instead of a browser dialog, and shows a per-provider sync report with the file each provider reads. Sync applies only to the Host the renderer is connected to; remote SSH and VirtualBox execution targets are not synced. Host routes are `GET /api/mcp/servers` (which runs the automatic adoption scan before returning the list), `POST /api/mcp/servers`, `POST /api/mcp/servers/import`, `PUT` and `PATCH` and `DELETE /api/mcp/servers/:id`, and `POST /api/mcp/sync`, all behind the native-shell lease.
