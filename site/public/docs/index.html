Current product status

No public desktop release yet

The repository contains a local prototype. This site keeps macOS disabled until a signed/notarized artifact is published and Windows disabled until the certified Microsoft Store listing is configured.

In the current prototype, Ensync Host can discover provider CLIs and run verified chats through authenticated Claude Code and Codex subscriptions. The broader catalog is visible for discovery, but it is not yet eligible for automatic chat routing.

Core concepts

One task above every provider

Project boundary

The selected project is the strict boundary for chats, context, memory, Git state, files, and terminal operations. A provider does not receive unrelated workspace context.

Shared feature memory

Durable decisions live in focused Markdown files within the project. Provider-specific instruction files remain thin adapters so the same facts are not copied into competing stores.

Conversation handoff

An Ensync task can retain the relevant transcript, feature plan, canonical project, project instructions, and verified Git branch while switching supported providers. Vendor session identifiers remain provider-specific.

Auto Context skill

The opt-in Auto Context mode preserves the selected project, conversation, decisions, provider-neutral Model size, and execution target. You can still use Auto or pin Codex/Claude. Automatic fallback remains a separate setting, and a safe handoff stays on the selected local or SSH/VM target.

Automatic priority and safe fallback

Settings keeps one persistent top-to-bottom priority list for Auto and fallback. Auto chooses the first connected, tested runner in that order with verified usage below 100%; a runner whose quota is unavailable is considered only after every provider with verified remaining usage. Runtime fallback advances through that same list only after Ensync Host proves the failure is safe to retry and no tool, command, file, or unknown activity occurred.

Is GitHub Copilot CLI an agent?

Yes. Ensync verifies the signed-in account automatically through Copilot CLI's SDK-compatible auth.getStatus method. The check starts the installed CLI in bounded headless stdio mode, creates no session, sends no prompt, and accepts only an explicit stored-user login and account name. Token environment variables and generic gh authentication are not accepted as proof.

“Discovery only” now refers only to Ensync's unfinished Copilot task runner and fallback integration. Account quota also stays blank because the auth response does not contain allowance or reset data. See GitHub's official SDK compatibility guide, local CLI setup, and Copilot CLI overview.

Usage

Provider-reported data only

Ensync does not calculate a subscription percentage from token totals. Quota percentages, plan names, model catalogs, and reset windows appear only when the provider exposes them through a verified, non-consuming CLI surface.

  • Codex usage and model data come from the initialized local app-server.
  • Claude usage comes from the CLI's local usage surface only when the structured event proves zero model turns, API duration, tokens, and cost.
  • Kimi stays unknown until Ensync has a version-gated, non-consuming quota probe. Its optional paid Extra Usage is never counted as subscription capacity.
  • Providers without a verified quota surface remain explicitly unknown.
  • Ollama is a local runtime, so it has local model and process capacity rather than a subscription percentage.

Releases

Verified release channels

The macOS button reads /releases.json and activates only for a matching signed/notarized HTTPS artifact with a real SHA-256 checksum.

The Windows button reads the public site configuration and activates only for an exact https://apps.microsoft.com/detail/... listing. Microsoft Store signs, installs, and updates that package. Missing or invalid release data always leaves the relevant button disabled.

Security

Credentials stay with official tools

Ensync is designed to launch fixed, allowlisted CLI login commands. It should not collect provider passwords or translate subscription authentication into provider API keys. Each vendor account remains subject to that vendor's terms, limits, and billing.

Before sharing diagnostics, remove passwords, bot tokens, API keys, SSH private keys, subscription cookies, and private source code that is not necessary to reproduce the problem.
