Privacy & billing

Clear boundaries.

A concise product model for local project data, provider credentials, subscription usage, diagnostics, and this static website.

Product model · Updated August 6, 2026

This is a product architecture summary, not a published legal privacy policy.

A formal policy must be reviewed and published before collecting accounts, analytics, payments, or support tickets.

Website data

This static website does not currently include analytics, account creation, payments, or a working support intake. It reads two same-origin JSON files: the release manifest and public site configuration. The light/dark preference is stored in the browser's local storage.

Provider subscriptions

Ensync is designed to use each provider's official CLI and account-based subscription mode. Subscription entitlements do not transfer between vendors. Your ChatGPT subscription backs Codex; your Claude subscription backs Claude Code; other providers use their own plans.

Ensync must not silently use per-token provider APIs as a fallback. A vendor may still impose its own limits, credit rules, terms, and billing.

Credentials

Provider authentication should remain inside the vendor's official CLI login flow. The desktop app should launch fixed, allowlisted commands and should not ask the website to receive passwords, API keys, subscription cookies, SSH private keys, or bot tokens.

Project data

The selected project is the context boundary. The local Ensync Host may inspect only the project context needed to run the requested task, including focused memory, root agent instructions, relevant transcript, and host-verified Git state. Provider CLIs receive data according to their own behavior and terms.

Usage telemetry

Provider usage is displayed only when returned by a verified provider surface. Ensync does not infer subscription percentages or reset windows from token counts. Missing telemetry remains unknown. Ollama is treated as a local runtime without a subscription quota percentage.

Support diagnostics

The help page currently creates a local report template; it does not submit data. Before any future submission, remove secrets and minimize private source content. A production help desk must publish its retention, access, deletion, and incident-response rules before accepting tickets.

Remote execution

Remote workers and Telegram access add separate trust boundaries. Their production release requires verified transport, strict project binding, explicit approval for risky actions, and documented credential storage. The public download site does not claim those capabilities are shipped.

Questions

A public privacy contact has not been configured. The website intentionally does not display a placeholder address. Check the help desk → for current contact availability.
